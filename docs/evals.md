## 2. The task, and why it is hard

A German letter rarely prints its deadline. It says *one month after this notice is announced to you*, and the date
depends on rules a reader has to know:

- A posted notice counts as delivered on the fourth day after posting since 2025 (the third before). Tax law moves
  that day off a weekend or a holiday; administrative law does not.
- A period that ends on a weekend or a public holiday ends on the next working day (§ 193 BGB), but a notice period
  does not move.
- Public holidays differ by federal state (Land).

On the test split's first run (2026-09-25), asked to work out the deadlines itself, the model got 10 of 56 wrong: 8
of those used the 3-day delivery rule that became 4 days in 2025, and all 4 late answers moved a deemed delivery day
off a weekend or holiday, which only tax law allows (from the explanations stored with each answer).

Ordnung's design bet ([ADR 0002](decisions/0002-llm-reads-code-computes.md)): the model **reads** the letter, what
it says about a date, and tested code **computes** the date, with a receipt for every step ([the
rules](deadline-rules.md)).

## 4. Conditions and baselines

The same model (`claude-sonnet-5`) reads the same letters under four conditions; each letter's “today” and holiday
region are the same in all four. Read as an ablation, they cross who computes the date with how the rules reach the
model:

| Condition | Who computes the date | How the rules reach the model |
|---|---|---|
| Ordnung | the rules engine | the model reads the letter into a structured reading; code finds each quote on the page |
| LLM only | the model | not at all: it is told today's date, the region and to apply current German law |
| LLM + rules text | the model | a verified summary of the rules, pasted into the prompt |
| LLM + rules tool | the model, calling the engine | Ordnung's engine as MCP tools: an agent with a calculator, which decides when to call it and whether to trust it |

*LLM only* is a floor; the rules-text prompt and the agent are the competitors. The tuning effort is unequal, in
Ordnung's favour: its extraction prompt went through several versions on the dev and test splits (the [history
page](evals-history.md) lists them), the baselines' prompts were tuned on the dev split.

## 5. Metrics

- **Exact date right** (primary): the share of dated deadlines whose final date is exactly the labelled one. A day
  off is wrong: a day late can miss a deadline and a day early asks for needless haste, and a tolerance would hide
  both.
- **Late** (after the real date), **missed** (not found) and **harmful = late or missed**, the safety metric: the
  person would act too late, or never. The scorer's *dangerously late* leaves a missed deadline out; it is still
  reported, as the CI gates use it. **Early**: before the real date, safe but wrong.
- **Letter fully right**: every dated deadline of the letter right and no spurious dated item. **Spurious dated
  items**: dated items the letter does not have.
- **$ per letter** and **per right date**: the API-equivalent price the Claude CLI reports. **Latency**: the model's
  time per letter, p50 and p95.
- **Flags**: what the person sees with a date: *Please check* (low confidence, or no date), *worth a second look*
  (medium confidence), or nothing.

## 13. From a letter to a reminder

Every letter of test, holdout, holdout2 and holdout3 read by the real app in a fresh data folder, from the recorded
readings, through to the calendar and the morning note (`python -m evals.e2e`,
`2026-10-30-claude-sonnet-5-e2e.json`): 209 of 224 genuine dated obligations got a reminder in time (93.3 %); 0 got
one only after the deadline. The stored dates equal the replay without the sender's Land for 224 of 224.

Not reminded, by cause: set aside as a scam: 15.

2 of 12 scam letters still put their demands in the calendar: `holdout3-adversarial-scam-1` (1 event) and
`holdout3-adversarial-scam-2` (2 events); 10 of 12 kept them off it (95 % CI 51.6–97.9). 2 of the 12 got no scam
warning (`holdout3-adversarial-scam-1` and `holdout3-adversarial-scam-2`). 13 of 240 genuine letters got a scam
warning by mistake (95 % CI 2.9–9.1).

## 14. Limitations

- The letters are synthetic, one or two clean pages each: real post is messier.
- The held-out splits were recorded with the code and prompts of their day; pooled, they mix versions.
- These statistics were chosen after the results were known: **not pre-registered**. The final run will be
  pre-registered before it is recorded.
- One read per letter: run-to-run noise is not measured yet (the final run reads each letter three times).
- The labels are code, audited by agents of the same model family; no lawyer reviewed the rules.
- The letter families leave out the rarer high-stakes kinds the engine covers; the final run adds a small set of new
  kinds.
- The benchmark gives Ordnung the Land on the letterhead; the app counts without it until the person sets or
  confirms it ([Results](#6-results), 6.4).
- Small numbers: against the rules-text prompt only 19 deadlines disagree.
- Ask is measured on the demo's own sample life, a development set, not held out.
- One model: `claude-sonnet-5`.

## 15. Reproduce

With no API key and no tokens, from a source checkout (`pip install -e '.[dev]'`), one command replays every split,
condition, Ask set, end-to-end run and ablation that has a recording, checks the analysis and these pages, and
compares every number with the [results index](../evals/results/INDEX.json): each file's hash, role and replay
verdict, a digest of every number the replay gives, and every date or count the code changed since its recording
with the fix that changed it. The per-item results are in [items.csv](../evals/results/items.csv) (ids, dates and
outcomes only).

```bash
make eval-reproduce                  # python -m evals.reproduce --check; CI runs it
```

Its parts, one at a time:

```bash
python -m evals.present --check      # this page, the README block, the history page, the charts
python -m evals.analysis --check     # the re-analysis every number here comes from
ordnung eval --split holdout3 --results-dir /path/to/replay   # a split replayed (any split)
python -m scripts.eval_without_land --out /path/to/replay   # the app without the sender's Land
python -m evals.ask                  # the Ask benchmark, replayed
python -m evals.present --site /path/to/site   # the report page
```

Recording costs tokens: `python -m evals.run --live --split <split> --model claude-sonnet-5` records answers the
replays above then reuse; the [history page](evals-history.md) states what each recording cost.

More: [every earlier run](evals-history.md) · [the Ask benchmark](evals-ask.md) · [the results
files](../evals/results).
